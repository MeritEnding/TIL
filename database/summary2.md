## 데이터베이스 시스템
데이터베이스에 데이터를 저장하고 조직에 필요한 정보를 생성해주는 시스템


## 데이터베이스 스키마
- 전체적인 데이터베이스 구조
- 데이터베이스에 데이터 구조와 제약조건들을 정의한다.
- 자주 변경되지는 않는다.

## 데이터베이스 인스턴스
- 스키마에따라 데이터베이스에 실제로 저장된 값
- 시간이 지남에따라 자주 변경된다.


## 3단계 데이터베이스 구조
- 데이터베이스를 이해하고 이용하기 쉽게 관점에따라 3단계로 나눈것
- 외부단계 : 개별 사용자 관점
- 개념단계 : 조직 전체의 관점
- 내부단계 : 물리적인 저장 장치의 관점
- 각 단계마다 추상화 레벨이 다르다

## 외부단계
- 데이터베이스를 개별사용자 관점에서 이해하고 표현하는 단계
- 데이터베이스 하나에 다수의 외부스키마 적용 가능
- 서로 다른 뷰를 제공한다
- 최종 사용자와 응용프로그래머들은 일부분에 데이터베이스만 관심이있다.

## 외부 스키마
- 외부 단계에서 사용자에게 필요한 데이터베이스를 정의한 것
- 사용자마다 논리적 구조가 다르다
- 서브 스키마라고 부르기도한다.

## 개념단계
- 데이터베이스를 조직 전체의 관점에서 이해하고 표현하는 단게
- 데이터베이스 하나에 개념 스키마 하나가 존재한다.
- 물리적인 구현 고려하지않고 전체에 관한 스키마를 포함한다.

## 개념스키마
- 개념단계에서 데이터베이스 전체의 논리적 구조를 정의한 것
- 조직 전체 관점에서의 데이터베이스
- 어떤 관계, 어떤 데이터, 어떤 무결성 제약조건이 있는지 기술

## 내부단계
- 데이터베이스를 저장 장치 관점에서 이해하고 표현하는 단계

## 내부스키마
- 실제로 저장장치에 어떤방법으로 데이터들이 저장되어있을까 기술
어떤데이터가 어떻게 저장되어있을까?
레코드, 필드, 인덱스,해싱에 대한정보

## 데이터 독립성
- 상위 스키마에 영향을 끼치지 않고 어떤 스키마의 정의를 변경할 수 있는 것
- 스키마 대응관계
외/개 -응용 인터페이스
개/내 -저장 인터페이스
 
- 논리적인 데이터 독립성: 개념스키마가 바껴도 외부 스키마에 영향을 끼치지 않아야됨
- 물리적인 데이터 독립성: 내부 스키마가 바껴도 개념스키마와 외부스키마가 영향을 받지 않아야됨
파일의 저장 구조를 바꾸거나 인덱스 생성 및 삭제

## 데이터베이스 사전
- 저장된 데이터베이스에 스키마 정보를 유지한다
- 시스템 카탈로그라고도한다.
- 데이터베이스에 저장된 데이터에 대한 정보 ,즉 메타 데이터를 유지하는 시스템 데이터베이스
- 데이터베이스 관리 시스템이 스스로 생성하고 유지한다.

## 데이터베이스 디렉터리
- 데이터 사전에 있는 데이터에 실제로 접근하는데 필요한 위치 정보를 저장하는 시스템 데이터베이스

## 사용자 디렉터리
- 사용자가 실제로 이용하는 데이터가 저장되어있는 일반 데이터베이스

## 데이터 언어
사용자와 데이터베이스 관리 시스템간에 통신 수단

## DDL 데이터 정의어
- 데이터베이스 스키마를 정의한다.
- 데이터 정의어로 명시된 문장이 입력되면 DBMS는 사용자가 정의한 스키마의 명세를 시스템 카탈로그 또는 데이터 사전에 저장한다.
- CREATE TABLE
- ALTER TABLE
- DROP TABLE
- CREATE INDEX

## DML 데이터 조작어
- 데이터베이스 내의 원하는 데이터를 검색하고, 수정하고, 삽입하고, 삭제한다.
- 절차적언어: 어떤 데이터가 필요하고 어떻게 데이터를 찾을 것인가
- 비절차적언어: 어떤 데이터를 원하는가만 명시
- SELECT, UPDATE,DELETE, INSERT

## DCL 데이터 제어어
- 내부적으로 필요한 규칙이나 기법을 정의하기 위해 사용
- 사용목적: 
무결성
보안
회복
동시성 제어
- 데이터 제어어를 사용하여 데이터베이스 트랜잭션을 명시하고 권한을 부여하거나 취소한다.

## 데이터베이스 관리시스템
- 데이터베이스 관리와 사용자의 데이터 처리 요구를 수행한다.

- 질의 처리기: 사용자의 데이터 처리 요구를 해석하여 처리한다.

- 저장 데이터 관리자: 디스크에 저장된 데이터베이스와 데이터사전을 관리하고 접근한다.

## 데이터베이스 시스템
- 중앙 집중식 데이터베이스: 데이터베이스 시스템이 하나의 커다란 컴퓨터 시스템에서 운영된다.
- 분산 데이터베이스: 네트워크 연결되어있는 여러 사이트에 데이터베이스가 분산
 서로 다른 사이트에 저장된 데이터베이스 접근 가능
- 클라이언트-서버 데이터베이스: 클라이언트를 통해 데이터베이스에 접근할 수 있다
 데이터베이스는 하나의 데이터베이스 서버에 저장되어있다
 2층 모델: 클라이언트 -서버
 3층 모델: 클라이언트서버 -응용서버- 서버


## 데이터 모델링
- 데이터베이스는 현실세계에 존재하는 수많은 데이터 중에서 조직을 운영하는데 꼭 필요한 데이터들을 선별해서 저장하는 것이다.
- 데이터 모델링: 현실 세계의 데이터들을 컴퓨터 세계의 데이터베이스로 변환하는 과정이다.
- 데이터베이스 설계의 핵심이다.

## 2단계 데이터 모델링
개념적 데이터 모델링
- 현실세계에서의 데이터를 개념세계에 옮기는 작업
논리적 데이터 모델링
- 개념세계의 데이터를 데이터베이스에 저장하는 구조로 표현하는 작업

## 데이터 모델
- 데이터 모델링의 결과를 표현하는 도구
- 개념적 데이터 모델: 사람이 이해 할 수 있는 데이터들을 개념적 모델링하여 개념적 구조로 표현하는 도구
개체-관계 모델

- 논리적 데이터 모델: 개념적 구조를 논리적 모델링하여 논리적 구조로 표현하는 도구
관계 데이터 모델

## 개체 관계 모델(e-r diagram)
- 실세계를 개체, 속성, 개체들 간의 관계로 표현한다.
- 개체 -관계 다이어그램
 개체 데이터 모델링을 이용하여 현실세계를 개념적으로 모델링한 결과물을 그림으로 표현한것

## 개체
- 현실세계에서 조직을 운영하는데 꼭필요한 사람이나 사물과 같이 구별되는 모든것
- 속성이 하나 이상이다
- 서점: 책, 고객
학교: 학과,과목

## 개체타입
- 개체를 고유의 이름과 속성으로 정의한 거

## 개체 인스턴스
- 개체를 구성하고 있는 속성이 실제 값을 가짐으로써  실체화된 개체

## 개체 집합
- 특정 개체타입에 대한 개체 인스턴스들을 모아 놓은 것

## 속성
- 개체나 관계가 가지고 있는 고유의 특성
- 하나의 개체는 연관된 속성들의 집합이다.

## 속성의 분류
- 속성값의 개수 : 단일 값 속성, 다중 값 속성
- 속성의 분해 여부: 단순 속성, 복합속성 
- 기존 속성에서 유도: 유도 속성

## 단일 값 속성
- 속성값이 하나인 속성
- 이름, 적립금 속성
## 다중 값 속성
- 속성값이 여러 개인 속성
- 연락처, 저자 속성

## 단순 속성
- 의미를 더 이상 분해 할 수 없는 속성
- 이름, 적립금, 가격 ,isbn

## 복합 속성
- 의미를 더 분해 할 수 있는 속성
- 주소, 생년월일

## 유도 속성
- 기존의 다른 속성들에 의해 유도되는 속성
- 나이, 가격
- 별도로 저장되지는 않는다

## 널 속성
- 널 값이 허용되는 속성
- 아직 결정되지 않았거나 모르는 값 또는 존재하지 않는 값
- 공백이랑 0이랑은 다름

## 키 속성
- 각 개체 인스턴스를 식별하는데 사용
- 모든 개체 인스턴스의 키 속성 값은 다르다

## 관계
- 개체와 개체가 맺고있는 의미있는 연관성

## 관계의 유형
- 관계에 참여하는 개체 수기준
 1. 이항 관계: 개체 타입 2개가 맺는 관계

 2. 삼항 관계: 개체 타입 3개가 맺는 관계

 3. 순환 관계: 개체 타입 하나가 자기자신과 맺는 관계

- 매핑 카디널리티 기준
 1. 일대일 관계
 2. 일대다 관계
 3. 다대다 관계

- 매핑 카디널리티?
관계를 맺는 두 개체 집합에서, 각 개체 인스턴스가 연관성을 맺고있는 상대 개체 집합의 인스턴스 개수

## E-R 다이어그램
1. 사각형: 개체
2. 타원: 속성
3. 마름모: 관계
4. 레이블: 매핑 카디널리티 표기
5. 링크: 각 요소 연결

## 논리적 데이터 모델
- 개념적 데이터 모델로 표현된 구조를 논리적 모델링하여 데이터베이스에 저장 될 수 있게 표현되는 논리적 구조
- 관계 데이터 모델, 계층 데이터 모델, 네트워크 데이터 모델


## 관계 데이터 모델은
- 데이터베이스의 논리적 구조가 2차원 테이블 형태

## 계층 데이터 모델
- 데이터베이스의 논리적 구조가 트리 형태
- 루트가 존재하는 형태
- 부모- 자식 상하관계(1:N)
- 다대다 불가능
- 삽입 삭제, 수정 이런게 힘듦
- 개념적 구조 모델링 힘듦

## 네트워크 데이터 모델
- 데이터베이스의 논리적 구조가 네트워크, 그래프인 형태
- 1:N 관계 오너와 멤버
- 다대다 불가능
- 이름 구별
- 삽입, 수정, 삭제 힘듦

# 5주차
## 관계데이터 모델
- 지금까지 제안된 데이터 모델 중에 가장 단순한 개념 중 하나
- 가장 인기많음
- 사용자가 원하는 데이터만 명시하고, 어떻게 그 데이터를 찾을 것인가는 명시 안해도됨
- 집합 위주 데이터 처리
- 간단한 테이블(릴레이션) 사용
- 개념적 구조를 논리적 구조로 표현하는 논리적 데이터 모델 중하나
- 하나의 개체에 대한 데이터를 하나의 릴레이션에 저장

## 릴레이션
- 하나의 개체에 대한 데이터를 2차원 테이블의 구조로 저장한 것
- 파일 관리 시스템에서 file

## 속성
- 릴레이션의 열, 애트리뷰트
- 파일 관리시스템에서 field

## 투플
- 릴레이션의 행
- 파일 관리 시스템에서 recode

## 도메인
- 하나의 속성이 가질 수 있는 모든 값의 집합
- 속성값이 삽입되거나 삭제될때 적합성 판단 기준

## 널
- 알려지지 않음 적용 할 수 없음
- 0이나 공백이랑 다른거
- 아직 모르는 값 아직 정해지지 않은값

## 차수
- 한 릴레이션에 들어있는 속성들의 수
- 유효한 릴레이션 최소 차수 1
- 차수는 자주 바뀌지않는다

## 카디날리티
- 릴레이션의 투플 수
- 유효한 릴레이션은 카디날리티 0을 가질수있다
- 릴레이션은 시간이 지남에따라 계속 바뀐다

## 릴레이션 스키마
- 릴레이션의 논리적 구조, 릴레이션 내포
- 릴레이션의 이름과 릴레이션에 포함된 모든 속성 이름으로 정의
- 정적
## 릴레이션 인스턴스
- 릴레이션에 존재하는 투플들의 집합,릴레이션의 외연
- 동적

## 데이터베이스 스키마
- 릴레이션 스키마의 모음
- 데이터베이스 전체 구조

## 데이터베이스 인스턴스
- 데이터베이스를 구성하는 릴레이션 인스턴스 모음

## 릴레이션 특성
- 릴레이션은 투플들의 집합
- 투플의 유일성: 하나의 릴레이션에는 동일한 투플이 존재 할 수 없다.

- 속성의 원자성: 속성 값으로 원자값만 사용할 수 있다.

- 투플, 속성의 순서는 상관없음
- 도메인 맞추고, 속성이름 다르게하고, 오직 하나의 레코드 타입만 포함

## 키의 종류
- 특정 투플을 검색하거나 다른 투플과 연관 시키려면 각 투플을 속성의 값을 이용해서 고유하게 식별 할 수 있어야한다.
- 키: 릴레이션에서 투플들을 유일하게 구별하는 속성, 속성들의 집합
- 기본키: 후보키 중에서 사용하려고 선택한 키
    cf 대리키: 자연스러운 기본 키를 찾을 수 없는 경우 인위적인 키 속성을 릴레이션에 추가할 수 있다.

- 후보키: 각 투플을 고유하게 식별하는 최소한의 속성들의 모임, 유일성 최소성 모두 만족
- 대체키: 기본키로 선택되지 못한 후보키
- 외래키: 다른 릴레이션의 기본키를 참조하는 속성 또는 속성들의 집합
    참조하는 릴레이션: 외래키를 가진 릴레이션
    참조되는 릴레이션: 외래키가 참조하는 기본키를 가진 릴레이션

- 슈퍼키: 한 릴레이션 내에 특정 투플들을 고유하게 식별할 수 있는 속성, 속성들의 집합

## 키의 특성
- 유일성: 하나의 릴레이션에서 모든 투플은 서로 다른 키값을 가진다.
- 최소성: 꼭 필요한 최소한의 속성들로만 키를 구성한다.

## 기본키 선택 사항
- 널 값을 가질수 있는 속성들이 포함된 후보키는 기본키x
- 값이 자주 바뀌는 속성들이 포함된 후보키는 기본키 x
- 단순한 후보키가 기본키에 적합하다

## 외래키
- 다른 릴레이션의 기본키를 참조하는 키
- 참조하는 릴레이션: 외래키를 가지고있는 릴레이션
- 참조되는 릴레이션: 외래키가 참조하는 기본키를 가지고 있는 릴레이션
- 외래키 속성과 그것이 참조하는 기본키 속성의 이름은 달라도되지만 도메인은 같아야한다
- 하나의 릴레이션에는 여러개의 외래키 가능하고 이것을 기본키로도 사용 할 수 있다.
- 외래키는 널값을 가질수 있고
- 같은 릴레이션에서 기본키를 참조 할 수있다.

## 무결성 제약조건
- 데이터 무결성을 보장하고 일관된 상태로 유지하기 위한 규칙
- 무결성? 데이터가 결함이 없는상태-> 정확하고 유효한 상태

- 4가지: 도메인 제약조건, 키 제약조건, 개체 무결성 제약조건, 참조 무결성 제약조건

## 도메인 제약조건
- 각 속성값은 원자성이 있어야한다.
- 디폴트로 정의 될수 있다
- 범위를 제한할 수 있다.

## 키 제약조건
- 각 애트리뷰트는 중복되서는 안된다
- 각 투플들이 유일하게 식별되야된다.

## 개체 무결성 제약조건
- 기본키를 구성하는 모든 속성은 널 값을 가지면 안된다.
- 대체키는 해당안돔

## 참조 무결성 제약조건
- 외래키는 참조할수 없는 값을 가질 수 없다.
- 두 릴레이션에서 연관된 투플들 사이에 일관성을 유지
- 외래키 값은 r1의 기본키이다
- 외래키 키가 r1의 기본키가 아니면 null


## 무결성 제약조건 유지
- 삽입: 참조하는 릴레이션에 새로운 투플을 삽입하면 신경써야함
- 삭제: 참조되는 릴레이션의 투플을 삭제하면 신경써야함
- 수정: 삭제하고 삽입하는거로 참조 되는 거 먼저 신경쓰고 참조하는 거 신경쓰기
- 전략:
    1. 제한 : 단순히 거절
    2. 연쇄 : 같이 삭제
    3. 널값 : NULL 대체


## 관계 데이터 연산
- 원하는 데이터를 얻기 위해서 처리요구를 수행하는 것
- 관계대수: 원하는 데이터가 있을 경우 얻을 수 있게 처리과정을 서술
- 관계해석: 원하는 데이터가 무엇인지만 기술

관계 대수, 관계해석의 역할
- 관계 대수, 관계해석으로 모든 질의를 기술할 수있으면 관계적으로 완전하다고 판단


## 관계해석
- 처리할 데이터가 무엇인지만 서술한다
- 비절차적 언어

## 관계대수
- 원하는 데이터가 있을때 릴레이션의 처리 과정을 순서대로 서술하는 것
- 릴레이션의 8개 연산의 집합
- 절차적언어
- 폐쇄적인 특징

## 일반 집합 연산자
- 릴레이션이 투플의 집합이라는 점을 이용하는 연산자
- 일반 집합연산자는 피연산자가 2개
- 합병가능 조건: 차수 같아야되고, 도메인이 같아야함
- 합집합, 교집합, 차집합, 카티션 프로덕트

## 합집합
- R에 속하거나 S에 속하는 것들을 모두 합한 모든 투플들로 릴레이션 구성
- 교환적, 결합적 특징
- R과 S의 카디널리티를 더한 값과 같거나 작아진다

## 교집합
- R에 속하면서 S에도 속하는 공통적인 것들의 투플들로 릴레이션 구성
- 교환적, 결합적 특징
- R과 S의 절대 어떤 카디널리티보다 크지 않다

## 차집합
- 릴레이션 R에는 존재하지만 릴레이션 S에는 존재하지 않는 투플들로 릴레이션 구성
- 교환적 ,결합적 특징 없음
- R과 R-S의 카디널리티가 같을수도있고 작을수도있음 반대도

## 카티션 프로덕트

- 릴레이션 R의 각 투플들과 릴레이션 S의 각 투플들끼리 모두 연결되어 새로운 투플로 새로운 릴레이션 구성
- 차수는 R의 차수 더하기 S의 차수
- 카디널리티는 R의 카디널리티 곱하기 S의 카디널리티
- 교환적, 결합적 특성 있음



## 순수 관계 연산자
- 릴레이션의 구조 특성을 생각하여 만든 연산자

- 셀렉트, 프로젝트, 조인, 디비전
## 셀렉트
- 릴레이션 R에서 조건에 맞는 투플들을 선택해 릴레이션 구성
- 하나의 릴레이션 대상으로 연산을 수행
- 비교식 , 비교연산자
- 결과 릴레이션은 연산 대상 릴레이션에 수평적 부분 집합
- 교환적 특징을 가진다

## 프로젝트
- 릴레이션에서 선택한 속성의 값으로 투플들을 반환한다 결과 릴레이션 구성
- 하나의 릴레이션에서 연산
- 결과 릴레이션은 연산 대상 릴레이션에 수직적 부분 집합
- 결과 릴레이션에 중복된 부분은 한번만 출력된다.

## 조인(자연조인)
- 두 릴레이션의 공통의 부분을 연결하여 새로운 투플을 생성하고 새로운 릴레이션을 구성
- 자연 조인

## 세타조인
- 주어진 조건에 만족하는 조인속성들을 묶어서 릴레이션끼리 연결하고 새로운 투플을 생성하고 새로운 릴레이션을 구성

## 동일조인
- 세타가 '=' 인 조인

## 디비전
- 릴레이션 2와 관련된 모든 투플을 릴레이션 1의 투플로 구성한다음 릴레이션으로 구성한다.

## 세미조인
- 조인 속성으로 미리 프로젝트 연산을 수행한 후 조인을 하는 것
- 불필요한 속성들을 미리 제거함으로서 연산 속도 올릴수있다, 연산 비용 줄일 수 있다

## 외부조인
- 자연 조인에서 제거되는 투플의 결과도 결과 릴레이션에 포함시키는 조인

## DBMS
- 데이터베이스를 정의하고, 질의어를 지원하고, 리포트를 생성하는 등의 작업을 수행하는 소프트웨어
- 조직에 필요한 데이터를 데이터베이스 통합하여 저장하고 관리한다

## DBMS 데이터 베이스 관리 시스템의 주요기능
- 정의기능: 데이터베이스 구조를 정의
